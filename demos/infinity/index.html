Infinities of different sizes

A hotel with infinitely many rooms, all full, can always fit more guests, even infinitely many busloads. But there is a kind of infinity no hotel can hold. Move the guests, then build a number that escapes every list.

Part 1

Hilbert's Grand Hotel

Rooms are numbered 1, 2, 3, and so on forever, and every room has a guest. Nobody may share a room, and nobody is left outside. You can only show the first sixteen rooms, but the rule you announce applies to every room at once.

Every move sends each guest to a room with a definite number, so anyone can work out where to go without waiting for anyone else. The zigzag is exactly how you list every fraction p/q, which is why there are no more fractions than whole numbers.

Same size or bigger?

Two sets are the same size if their members can be paired off one to one, with nothing left over. Any set you can arrange in a list (first, second, third, …) is "countable" and the same size as the counting numbers.

Cantor's diagonal argument

Suppose someone hands you a numbered list that, they claim, contains every infinite string of digits. Go down the diagonal: change the 1st digit of row 1, the 2nd digit of row 2, and so on. The result differs from every row in at least one place, so it was never on the list.

What you're seeing

In the hotel, every rule is a one-to-one pairing between guests and room numbers. "1 new guest" uses n → n + 1. "A bus" uses n → 2n for current guests and the odd rooms 2k − 1 for passengers. For infinitely many buses, the zigzag walks the grid of (bus, seat) along its diagonals; the prime-power plan sends current guests to 2n and bus b's passengers to the b-th odd prime raised to the seat number.

In the diagonal grid, row k is the k-th string on the list. Binary digits are flipped. Decimal digits become 5, or 4 if they were already 5, which avoids the 0.0999… = 0.1000… double-spelling problem.

Each rule is one formula applied to every room number at once, so no guest has to wait to see where anyone else goes. The page evaluates the same formulas for the 16 rooms and the first few seats of each bus it has space to draw. A guest whose new room is above 16 slides off to the right; the room still exists.

  • Add the diagonal string to the list three times. Each time a brand new escapee appears.
  • Change a digit that lies on the diagonal and watch the matching digit of the new string change too.

Why it's strange

For finite sets, a part is always smaller than the whole. For infinite sets that fails: the even numbers are half of the counting numbers, yet pair off with them perfectly. Galileo noticed this with square numbers in 1638 and concluded infinite sets can't be compared. Cantor showed they can, and that they don't all match.

His 1874 paper proved the real numbers can't be listed; the diagonal argument of 1891 made it a one-line idea and showed there is no largest infinity at all. Whether any size sits between the countable and the reals (the continuum hypothesis) turned out to be unprovable either way from the standard axioms (Gödel 1940, Cohen 1963).

Written as sizes, the hotel's moves say ℵ₀ + 1 = ℵ₀, ℵ₀ + ℵ₀ = ℵ₀ and ℵ₀ × ℵ₀ = ℵ₀. The diagonal works on any set: the collection of all subsets of a set is always strictly bigger than the set itself (Cantor's theorem). So 2ℵ₀ is bigger than ℵ₀, the subsets of the reals are bigger again, and the ladder of infinities never ends.

The math

f(n) = n + 1    g(n) = 2n    h(k) = 2k − 1

The three simple moves. Each is one-to-one: two different inputs never give the same room. f frees room 1 for the new guest, g puts the current guests in the even rooms, and h puts the passengers of one bus in the odd rooms. Between them g and h use every room exactly once, which is the statement ℵ₀ + ℵ₀ = ℵ₀.

π(b, k) = s(s + 1)/2 + b + 1,    s = b + k − 1

The zigzag, known as Cantor's pairing function. Bus b, seat k lies on diagonal s of the grid. The diagonals before it hold 1 + 2 + … + s = s(s + 1)/2 cells, and b counts the steps along its own diagonal. Every pair gets a different room and every room is used, so pairs of counting numbers are no more numerous than the counting numbers: ℵ₀ × ℵ₀ = ℵ₀. The hotel guests are bus 0, so room n goes to π(0, n) = n(n − 1)/2 + 1: rooms 1, 2, 4, 7, 11, … This is exactly the formula the page uses.

(b, k) ↦ pbk,    p0 = 2, p1 = 3, p2 = 5, p3 = 7, …

The prime-power plan. Every whole number above 1 factors into primes in only one way, so a power of one prime never equals a power of another, and no two guests collide. Numbers that are not prime powers, like 6, 10, 12 and 15, are never assigned, and seats start at 1 so room 1 also stays empty. One-to-one is all the hotel needs; filling every room is optional.

dj ≠ ajj  ∀j   ⇒   d ≠ ai  ∀i   ⇒   ℵ₀ < 2ℵ₀ = |ℝ|

aij is digit j of row i, and d is the new string. Because d differs from row i at digit i, it matches no row, whatever the list. In binary the page sets dj = 1 − ajj; in decimal it writes 5, or 4 when the diagonal digit is 5. Infinite strings of 0s and 1s match the subsets of the counting numbers (1 at position n means n is in the subset), so there are 2ℵ₀ of them, the same number as the real numbers. The page makes each row's digits from a hash of the row and column numbers, so any digit of the endless list can be looked up on demand.

Real-world applications

Where the diagonal sets hard limits

Cantor's trick turned into one of the most useful ideas in logic and computer science. Wherever you can list all the things of one kind, the diagonal builds something outside the list, and that marks out what computers and proofs can never do.

Computer science

The halting problem

In 1936 Alan Turing proved no program can decide, for every program and input, whether it will eventually stop. List all programs; a "contrarian" program that does the opposite of what the checker predicts for program k on input k differs from every program on the list. Every program analyser lives with this limit.

In the demo: row k, digit k, flipped.
Security

No perfect virus scanner

Fred Cohen showed in 1987 that deciding whether any given program is a virus is undecidable, by the same diagonal reasoning. Rice's theorem extends it to any non-trivial question about what a program does. Real scanners use signatures and heuristics, and accept missing some threats or flagging some safe files.

In the demo: whatever list of verdicts you write, the diagonal dodges it.
Logic

Gödel's incompleteness

In 1931 Kurt Gödel coded every formula as a single number using products of prime powers, then built a statement that in effect says "I am not provable". Any consistent system strong enough for arithmetic has true statements it cannot prove.

In the demo: the prime-power plan packs many sequences into one numbering.
Numerics

Uncomputable numbers

Every program is a finite string of symbols, so programs can be listed, and the numbers some program can print digit by digit are countable. The reals are not. So almost every real number has no program that computes it, and computers only ever work with a thin, countable slice of the number line.

In the demo: fill the list with every computable number; the diagonal is still missing.
Programming

Pairing functions

The zigzag gives a formula that turns any pair of whole numbers into one whole number and back, known as the Cantor pairing function. Programmers use it and its cousins to key a table by two numbers at once, such as grid coordinates, and logicians use it to encode pairs, lists and programs as single numbers.

In the demo: bus b, seat k → one room number.
Data

Compression limits

There are 2n files of n bits but fewer than 2n shorter files, so no lossless compressor can shrink every file; some must stay the same size or grow. It is the same counting-by-pairing idea Cantor used, applied to finite sets, and why zipping a zip file doesn't help.
